# 批处理富化作业细则(一次性)

> 权威:同目录 `SKILL.md`(先完整读一遍,尤其**「首要规则」**);冲突以 SKILL.md 为准。本文只补"批量作业"的操作细节。

## 1. 任务

给 draft JSON 的每句补 `zh` / `words` / `note`。**`start`/`end`/`en` 就是原 SRT cue 的原样值——逐字符不许动**:不合并、不拆分、不补标点、不改大小写、不"修"语法口误。句子长短(20 词、30 词或半句话碎片)不用管,长度不是拆分的理由,也不是合并的理由。

## 2. 逐文件流程

1. **读 draft .json 全文**(先通读再动笔;留意角色名,译名全批保持一致。常见:Steve=史蒂夫,Maggie=玛吉)。
2. **逐句富化**(标准见 SKILL.md §3 表格):
   - `zh` 必填:准确、自然、口语化,儿童动画对白口吻;碎片句按碎片译(不补全),重复的歌词句可自然地重复;
   - `words` 每句通常 0–5 个(软上限,别堆砌):**优先挑常用词组/固定搭配/短语**(boys and girls / wake up / clean up / here you are),其次才选启蒙高频单字;不选 the/a/单一代词;同一文件内同一条词组/单词只讲一次,名额留给新词;选全别漏(如 `boys and girls` 别只留 `boys`);
   - `words` 每条的 `w`:用 en 中的**表层连续片段原样**(词组含中间空格,单字含 can't / doing / girls),照 en 逐字不增删、不改词序、不还原词干;`note` ≤20 字,讲"整条什么意思、怎么说、什么时候说";**不写 `phonetic`(已废弃)**;
   - 句级 `note` ≤40 字,只写句型/语法点,宁缺毋滥(没把握就不写这个键)。
3. **写回**:用 write 工具整文件重写,2 空格缩进、UTF-8 无 BOM(不要用 PowerShell Set-Content)。`start`/`end`/`en` 从你读到的 draft **逐字复制**(包括标点、大小写、省略号);只允许增加/修改 `zh`/`words`/`note` 三类键,不加任何其他字段。
4. **写完立即校验(逐文件)**:

   ```
   backend\.venv\Scripts\python.exe .agents\skills\srt-to-json\scripts\srt_tool.py check "<同名.srt>" "<该.json>"
   ```

   必须 `OK`(0 ERROR)。若报"句数不一致 / 时间戳不对齐 / en 不一致"= 你改坏了结构:按 draft 原样恢复(拿不准就对该文件跑 `draft --force` 重生成结构后重做富化),修到全绿。WARN 不拦截,记录即可。若你的环境不能执行命令,跳过并在回报中注明"未跑 check"。
5. 不碰分配清单以外的任何文件;不要对未分配的文件夹跑 `draft --force`。

## 3. 回报格式(全批做完后)

- 每文件一行:`文件名 → OK`(或 `WARN n`);未跑 check 的注明"未跑 check"。
- 不确定项:拿不准的译名/音标/存疑台词(没有就写"无")。**不再有"断句调整"一项——结构禁止调整。**
