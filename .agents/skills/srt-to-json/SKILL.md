# SRT → 带学练习卡 JSON(V2.0 提炼式)

权威分工:数据结构以本 skill 目录下的 `subtitle.schema.json`(JSON Schema,机器可读)为准;校验分层、存储传输等 app 侧说明见 `docs/v2.0.md` 与 `docs/v1.0.0.md`;**生产流程与质量要求的唯一权威是本文件**。数据结构冲突以 schema 为准,流程冲突以本文为准。

## 产品定位(V2.0 为什么改)

播放页不再展示"全量今日台词"——看片时的字幕由**浮层 srt 轨**(卡拉OK高亮)独立负责,与本 JSON 无关。教学 JSON 只服务两件事:**孩子练**(重点单词、短句跟读评分,亲子对话演出来)和**家长带**(带学脚本:播前/播中/播后怎么引导)。因此不再逐句富化全部台词,只**提炼**一集里最有教学价值的部分,把预算花在刀刃上。

## 首要规则(凌驾一切,违反即返工)

**原声句是一等公民,`sentences` 是它的「重点子集」。** JSON 的 `sentences`(3–6 句)必须每条**逐字逐秒**来自 SRT 清洗合并后的某个原声句:第 i 条的 `start/end` 就是那个原声 cue 的起止时间,`en` 就是它的清洗后文本,**逐字符一致**。

- **卡拉OK式逐词高亮源由脚本机械合并**(唯一允许的合并,由 `srt_tool.py` 在 draft/check 里自动完成):同句每高亮一个单词就重复一条 cue,剥掉标签后文本完全一致 → 合并为一句,时间取并集。除此之外禁止合并/拆分/改写原声句。
- **重点短句只能「选」,不能「造」**:不许把两句并成一句、不许截半句、不许补标点/改大小写/顺语法。选哪句是判断题,改写是红线。
- **`words` 是全集词块**:每条 `w` 必须是本集原声全文(所有 cue 文本拼接)的表层连续片段(1–3 个词),照原样不还原词干。
- **`dialogues` 与 `guide` 是生成内容**(不是原文):从本集内容拓展到孩子的日常生活场景,地道、启蒙词汇量内。
- 机器拦截:`check` 逐句比对子集句与原声 cue 的文本/时间戳,词块比对全文 token,任何漂移直接 ERROR,修不绿不交付。

## 架构取舍(为什么这样分层)

- **结构层**(解析/清洗/候选池)= 本地确定性脚本:时间轴、cue 文本必须可复现、可 diff——`en` 是跟读评分参考文本的地基,不交给概率性组件
- **语义层**(选句/提炼词块/编对话/写带学脚本)= 执行本 skill 的 agent(即 LLM):LLM 强于判断和创作的地方;失败可整体重做,不污染结构
- **不建独立的 LLM API 批量工具**:agent 本身就是 LLM 路径,外部脚本是重复实现;单机月度量级(≈30 视频)下无收益

## 红线(违反即返工,check 子命令会机器拦截)

1. **重点短句的 `en` 逐字冻结**:必须从 draft(或旧 json)逐字复制,`start/end` 逐秒复制;改了评分与跳转全错,没有任何例外
2. **`words.w` 是本集全文的表层连续片段**:单词/词组皆可(如 `fix it`、`boys and girls`),照原声原样:不增删词、不改词序、不还原词干(把 `doing` 写成 `do` 就错位)
3. **`phonetic` 已废弃、不再生成**(顶层 words 板无此键;旧数据兼容不校验)
4. `.json` **UTF-8 无 BOM**(BOM 会让按月导入把该视频整体跳过,原因"字幕 JSON 无效")
5. 重点短句按 `start` 升序、不重复选同一句;`end > start`
6. `dialogues.lines[].speaker` 只能是 `parent`/`child`;所有 `en` 无 HTML 标签、无首尾空白
7. `guide.goal/before/after` 必填(生成契约),`during/tips` 可选;所有条目非空
8. 四板(`words/sentences/dialogues/guide`)至少一板存在;数量软上限超了只 WARN,但别堆砌
9. check 有 ERROR 不交付;交付验收(流程 §5)走完才算完成

## 流程

### 0. 前置确认

- 月度文件夹形态:`NN_标题.mp4` + 素材同名文件夹 `NN_标题/`(内含 `NN_标题.srt`)
- **成品 JSON 落盘位置(导入契约,硬规则)**:素材同名文件夹内的同名文件 `NN_标题/NN_标题.json`,与 mp4 同级——后端导入只查这个位置(`main.py` 导入端 `f.parent / f.stem / (f.stem + ".json")`)。`draft` 自动落盘到该位置,`check` 按同一路径查找;成品 json 不要手工挪动
- 已存在同名 `.json` 时先问用户是否重做(重做加 `--force`,会覆盖已提炼内容;批量再生成走 BATCH_BRIEF.md)
- 量大时(整月)一次会话做一支视频,做完一支 check 一支,不攒批——超长会话质量会漂移

### 1. 结构层(跑脚本,确定性)

```
backend\.venv\Scripts\python.exe .agents\skills\srt-to-json\scripts\srt_tool.py draft <文件夹|单个.srt> [--force]
```

脚本做:去 BOM/GBK 降级解码 → 逐 cue 清洗(HTML 标签、♪/`[music]` 注解行、说话人标签 `JOHN:`)→ 源时间轴缺陷规范化 → **卡拉OK相邻同文 cue 机械合并** → 写入素材同名文件夹 `NN_标题/NN_标题.json`(`{"sentences": [全量 start/end/en 骨架]}`)。**这个全量骨架就是下一步提炼的候选池**,保持原样备用。

- 脚本纯标准库,任何 Python 3.10+ 可跑;`backend\.venv` 可能损坏(基础解释器被删),届时换系统里的 Python(如 `D:\tools\py311\python.exe`)即可
- 清洗规则集中在 `_clean()`:要改就改脚本后重跑 `draft --force`(会覆盖已提炼内容,慎用),不手改 JSON

### 2. 语义层(AI 提炼,核心步骤)

**先通读候选池全文再动笔**:记下标题语境、角色名、口头禅的既有译名,全片(乃至同月系列)保持一致;常见译名:Steve=史蒂夫,Maggie=玛吉。

从骨架提炼四板(先看 §3 质量表):

| 板块 | 做什么 |
|---|---|
| `sentences` 重点短句 3–6 句 | 选**最值得跟读的原声句**:完整、短(≤10 词优先)、句型典型、启蒙高频;`en/start/end` 从候选池逐字逐秒复制,再补 `zh`(必填)、`note`(可选,≤40 字句型点) |
| `words` 重点单词 4–8 条 | 选**最该掌握的词块**:常用词组/固定搭配优先(`fix it`、`wake up`、`here you are`),其次启蒙高频单字;不选 the/a/单一代词;同一条词组只讲一次。`w` 照原声原样,`zh` 必填,`note` ≤20 字 |
| `dialogues` 亲子对话 1–3 个 | 把本集的核心词句**迁移到日常生活场景**(玩具坏了/吃饭/起床),parent/child 交替 4–8 行,每行启蒙可说出口的长度;`scene` 中文场景名,`tip` 给家长玩法提示(拿真玩具演/边做边说) |
| `guide` 家长带学脚本 | `goal` 一句话目标;`before` 播前钩子 1–2 条(中文,勾期待、带问题看);`during` 播中互动(TPR:视频里喊 Jump 就一起跳),可选;`after` 播后提问 1–3 条(引导说出核心词句);`tips` 家长自身发音难点,可选 |

写回:用 write 工具整文件重写,2 空格缩进、UTF-8 无 BOM;`sentences[].en/start/end` 从骨架**逐字逐秒复制**;四板之外的键不加。

### 3. 质量标准(每板的核心要求)

- **选句眼光**:一集看完孩子该记住的"钩子句"——重复出现的主题曲句、目标句型的实例、情感高点的短句;歌词型碎片/超长旁白不选
- **选词眼光**:换个场景孩子还能用的词块优先(会用 `broken` 描述任何坏东西);纯剧情词(角色名/本集特有名词)不选
- **对话眼光**:是"演出来的对话"不是"课文"——行短、可配动作、有来有回;把本集 1–2 个核心词块自然嵌进去,别硬塞
- **带学眼光**:before 是给家长照着说的话术,不是抽象建议(❌"激发孩子兴趣" ✅"跟孩子说:今天看小猴子修自行车,你猜车会坏在哪?");after 的问题要能用英语核心词回答
- **zh 译名一致**:同一角色/口头禅全批一致

### 4. 校验(必须 0 ERROR)

```
backend\.venv\Scripts\python.exe .agents\skills\srt-to-json\scripts\srt_tool.py check <文件夹>
```

脚本校验:子集句逐条比对原声 cue(文本+时间戳)、词块全文子序列、对话结构+speaker 枚举、guide 必填键、空文本/HTML 残留。WARN(数量超软上限/疑似旧格式)不拦;ERROR 必须修完重跑直到全绿——"不对齐/不是原声句"类 ERROR 说明结构被改过,按 draft 原样恢复。

### 5. 交付与验收(闭环,走完才算完成)

1. check 全绿
2. 抽样自检:每支视频抽 1 句短句+1 条词块+1 段对话逐项过 §3,不合格回头改
3. 导入:Admin 页按月导入该文件夹(或 `POST /api/admin/courses/import`);幂等键 `rel_path`,同文件重导覆盖且 id 稳定。**后端零改动**(V2.0 起 normalize_subtitle 按新契约校验)
4. 核对导入结果:返回的 `skipped[]` 里不能出现"字幕 JSON 无效";出现 = 回 §4 排查该文件

## 存量迁移(207 集旧格式 → V2.0)

旧 json(全量逐句富化)重新提炼为四板,**批量作业走 `BATCH_BRIEF.md`**(含备份规则);要点:旧 json 的 `zh/words/note` 是现成参考,`en/start/end` 可直接从中复制子集(与从 draft 复制等效,check 都会校验)。

## 自检(改过脚本或 schema 后必跑)

```
backend\.venv\Scripts\python.exe .agents\skills\srt-to-json\scripts\srt_tool.py selftest
```

## 边界

- 不做 ASR 字幕生成(项目非目标);前提是已有 SRT 文本
- 转换是导入前的离线一次性步骤,App 运行时零云依赖不变
- 不做 `difficulty` 字段、不做 import 端 srt 兜底——真有需求再议
