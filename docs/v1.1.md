# EnLearn V1.1 · 迭代方向

> 评估时间 2026-09（V1.0 完成后）。结论：**下一刀 = 评分落库**（学习深化的前置）；复习（SRS）保持不做，只留明确触发条件。

## 主方向：评分落库（给跟读循环装上记忆）

为什么是它：

- 跟读弹窗是全应用最重投入的交互，但结果关闭即弃——云 API 的钱花了，数据没留下；"这个月的 Wednesday 比上月进步没有" 现在无法回答
- 设计已预留：V1.0 明确"将来要历史只需加 `scores` 表 + 评分返回体原样入库"，弹窗/评分链路 100% 复用
- 必然被使用：挂在每次评分之后自动发生；历史展示放每天都会打开的弹窗里
- 零增量成本：存的是已付费调用的结果

第一刀（最小可用）：

- 表 `scores(id, material_id, sentence_index, reference, accuracy, fluency, completeness, created_at)`
- `/api/score` 成功后同步 INSERT（零新端点）；弹窗按 `(material_id, sentence_index)` 查最近/最佳
- UI：结果区加一行「第 N 次练习 · 上次 72 · 最佳 85」
- 天花板（自用可接受）：重导字幕后 `sentence_index` 可能漂移，历史可能挂错句

## 候选方向（排序）

1. **听写模式**：TTS 念句 → 输入 → 文本比对；零云成本、纯复用 sentences/TTS，补上"主动回忆"缺口
2. **生词标记 / 句子收藏**：基于词块数据，价值后置（攒词需要出口）
3. **低分句重练清单**（复习的惰性版）：依赖落库数据先行

## 复习的触发条件（三条都出现才立项）

1. 落库跑数周，积累真实低分数据
2. 出现"手动翻历史想重练某句"的行为
3. 通过"重排旧素材自然重看"没有自发发生

届时只做「低于门槛分的句子平铺列表，点击进现有弹窗」——**不做 SM-2 / 艾宾浩斯 / 到期队列 / 复习打卡**。

## 明确不做

- SRS 调度 / 到期队列 / 复习打卡：精听练的是技能（听觉解码、口肌自动化），与离散事实记忆的 SRS 错配；且与日历打卡习惯争夺意志力、建设成本最大、放大云调用次数
- 独立"复习中心"页面：触发条件未满足前不立项
